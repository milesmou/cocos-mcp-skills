# 规划与拼装 Cocos UI

执行前读 [MCP 协作流程](mcp-workflow.md)。节点、组件、资源、事件和预览操作通过 MCP 完成，工具参数与可选桥接能力统一查看服务文档。

用一个连续流程完成 UI 结构分析、Prefab 蓝图、编辑器拼装和验收。先形成符合目标工程的结构规格，再决定是否写入工程；不要用通用 UI 模板覆盖已有控制器、引用、资源和 Prefab 复用关系。

## 请求边界

- 用户只要求“分析、规划、节点树、蓝图”时，只完成规划阶段并交付蓝图，不修改工程。
- 用户要求“创建、制作、拼装、实现、重构、修复”时，先补全或校验蓝图，再在同一任务中继续执行和验收；已有制作授权时不额外等待确认。
- 用户要求给已经拼装的 UI“补资源、换正式图、替换美术、换皮”时，保留现有功能结构，只执行与新资源有关的必要修改，并完成换装回归；不要重新按首次拼装流程创建界面。
- 用户给出完整蓝图时仍先检查工程契约。发现与脚本、资源或现有 Prefab 冲突时，按证据修正规格并记录原因。
- 只有会改变结构且无法合理推断的必要信息缺失时才询问用户。其余未知项标记为“待确认”或带依据的“估算”，继续不依赖该信息的工作。

始终读取 [references/blueprint-rules.md](../references/assemble-cocos-ui/blueprint-rules.md) 和 [references/ui-rules.md](../references/assemble-cocos-ui/ui-rules.md)。需要输出蓝图时使用 [references/blueprint-template.md](../references/assemble-cocos-ui/blueprint-template.md)。项目专用结构、组件和业务规则从目标工程已读取的 `AGENTS.md` 及其指定文档获取，并核对当前实现，不按组件名称自动加载其他项目的规范。输入包含效果图时必须读取 [references/visual-fidelity.md](../references/assemble-cocos-ui/visual-fidelity.md)。已有 UI 需要补充或替换正式美术、字体、状态图或嵌套视觉 Prefab 时，必须读取并执行 [references/art-replacement.md](../references/assemble-cocos-ui/art-replacement.md)。
涉及生图、切图、合图或从效果图拆分 SpriteFrame 时，还必须读取并执行 [references/art-slicing.md](../references/assemble-cocos-ui/art-slicing.md)。必须在生图或切图之前依据效果图和项目设计分辨率确定每个素材的正式输出像素尺寸、透明留白及锚点/接口位置，并写入素材规格表；未确定不得开始制作。随后按规格输出 PNG、核对实际文件尺寸，再导入 Creator。禁止生成后临时决定正式尺寸，或直接导入大尺寸制作源图，仅靠节点缩放满足显示尺寸。

命令中的 `<技能根目录>` 替换为本技能集合所在目录的绝对路径，`<工程目录>` 替换为目标 Cocos 工程绝对路径；保留路径引号，不依赖当前工作目录。

## 识图与计算

先测量效果图画布、元素包围框、间距、文字和状态，再计算到工程设计分辨率的坐标映射。采用分析结果前核对原图尺寸、设计分辨率和关键锚点，不将未复核的估算直接写入工程。

资源较多时，使用 `<技能根目录>/scripts/build-visual-asset-catalog.py` 生成编号、路径、尺寸、透明边界和分页图册，结合图像与工程引用确认候选资源。根据任务规模按需检查图册，不仅凭文件名猜测。

## 工程设计分辨率

Creator 3.8 工程通常从 `settings/v2/packages/project.json` 的 `general.designResolution` 读取 `width`、`height`、`fitWidth` 和 `fitHeight`，开始设计前读取当前配置，记录来源与适配开关。字段缺失时按目标版本核实来源，不以历史样本、Prefab 根尺寸、效果图或预览窗口尺寸代替工程设计分辨率。

## 规划阶段

1. 收集证据。
   - 读取用户提示、效果图尺寸、可见内容、资源范围、目标 Prefab 和控制脚本。
   - 有现成 Prefab 时，通过 MCP 查询真实层级、组件、激活状态、资源和 Prefab 实例，不凭截图或文件名推断。
   - 按 [工程设计分辨率](#工程设计分辨率) 读取当前配置及适配设置，再读取同业务目录内容，从同职责 Prefab 中选择 1 至 3 个结构参考。不要把全工程统计直接当作单个界面的模板。
2. 判断 Prefab 职责：全屏窗口、弹窗、HUD、可复用控件、列表项、状态节点或纯视觉特效。由职责决定根尺寸、控制器、内容容器和适配方式。
3. 提取结构契约。
   - 标出根控制组件和每个嵌套控制器、项目引用收集器的实际作用域。
   - 搜索脚本使用的节点名、引用 key、按钮名、固定索引和子节点路径。这些名称和顺序属于代码接口。
   - 标出按钮事件归属、项目状态组件的状态顺序和默认值、初始 inactive 节点、AnimationClip 目标路径和排序边界。
   - 区分本地序列化节点、嵌套 Prefab 实例、固定设计槽位、运行时模板和运行时生成内容。
4. 有效果图时锁定视觉基线：原图像素尺寸、方向、背景或透明通道、文本、语言、数据、滚动位置、状态组、动画时间点和安全区。逐项记录资源模式：
   - 已提供或能在工程中唯一定位对应资源：精确资源模式。
   - 对应资源缺失：纯色占位模式。
   - 按 [设计分辨率映射](../references/assemble-cocos-ui/visual-fidelity.md#直接使用工程设计分辨率) 确定画布和坐标换算，记录缩放与留白偏移；设备适配单独检查。
   - 需要生图或切图时，在任何制作操作之前按 [真实尺寸切图规则](../references/assemble-cocos-ui/art-slicing.md) 完成素材规格表，明确正式输出尺寸及其计算依据。生图尚无来源图时先记录计划制作画布尺寸；生成后核对实际来源尺寸，按已确定的规格输出，不能反过来用生成结果决定正式尺寸。切片矩形必须由真实包围框和适配缩放计算得到，不得凭目测或先把整张图缩放后再猜边界。
5. 按“根与控制边界 → 嵌套 Prefab → 功能容器 → 固定槽位与模板 → 叶子节点”的顺序规划。节点规格表是尺寸、位置、锚点、激活状态和组件属性的唯一事实来源；树只表达父子关系、渲染顺序、来源和组件概览。
   - 不要把一个功能区域的标题、背景、内容和控件全部平铺到页面根或面板根。两个及以上同职责节点应归入语义明确的区域容器，但不得破坏已有脚本路径、动画轨道或 Prefab 实例边界。
   - 按钮可见文字必须放在对应 Button 节点的子树内，通常作为直接子 Label；不得让按钮与其文字成为同级节点。
   - 识别文字、图标、徽标等覆盖元素与其底板、标题牌、按钮背景之间的视觉绑定。会随承载素材一起移动或缩放的元素必须放在承载节点子树内，或与承载素材共用一个零偏移容器；规格同时记录承载素材的绝对位置和覆盖元素相对承载素材的局部偏移。
6. 使用蓝图模板输出：分析摘要、结构证据、完整节点树、控制器和引用作用域、Prefab 实例、关键规格、重复内容、状态、视觉、交互、适配、拼装顺序及待确认项。
7. 执行蓝图一致性检查：
   - 本地节点路径唯一，父路径存在，命名遵循目标工程。
   - 引用 key 在所属收集器作用域唯一，嵌套边界未被跨越。
   - 每个按钮只归属一个控制器，按钮名与控制脚本一致。
   - 项目状态组件的节点顺序与实际索引/名称约定一致；固定槽位未被误判为模板。
   - 嵌套 Prefab 没有被展平；实例资源、属性覆盖和运行时生成关系明确。
   - AnimationClip 路径、脚本路径查询、排序边界和默认激活状态完整。
   - Layout、Widget、动画与手动坐标在同一属性上没有控制冲突。
   - Mask 是 Content 的祖先；ScrollView 的 viewport、Content、方向和引用方式完整。

用户只要求分析或规划时，到此交付蓝图并结束。用户要求实际制作时继续执行以下阶段。

已有 UI 只需替换美术资源时，不重新创建根节点或功能结构。先按 [references/art-replacement.md](../references/assemble-cocos-ui/art-replacement.md) 固定换装前基线和替换清单，再复用下面的结构校验、保存和视觉验收步骤。

## 拼装阶段

8. 确认 MCP 连接与当前编辑对象，按蓝图组织节点、组件、资源、Prefab 和事件操作。记录用户已有上下文与布局基线；使用实际节点及组件状态，只有对应桥接已安装时才使用其 `inspectUILayout` 辅助方法。
9. 核对目标 Canvas、目标 Prefab URL、资源 UUID、可复用 Prefab 和实例边界。优先复用工程中承担相同职责的控件；确认对应资源不存在后才能创建纯色占位视觉。
10. 先创建根节点和控制边界，再实例化公共 Prefab，随后创建功能容器、固定槽位、模板和叶子节点。每次创建后记录返回 UUID；同级重名时只用 UUID 操作。
11. 按以下顺序配置：
    - 未指定 Layer 时，将新建 Prefab 根和自建后代设置为 `UI_2D`（`33554432`）；不要改写嵌套 Prefab 内部节点。
    - 添加 `UITransform`，先根据元素与父容器的定位关系确定尺寸和锚点，再计算节点局部坐标；不能使用默认锚点计算后再改锚点。
    - 添加 Sprite、Label、Mask 等视觉组件并绑定资源。字体回退与描边遵循 [文字组件规则](../references/assemble-cocos-ui/ui-rules.md#text-decoration)，先确定对齐、Overflow 和尺寸再定位；素材与占位遵循 [占位规则](../references/assemble-cocos-ui/ui-rules.md#placeholder-visuals)。
    - 对生图或切图得到的正式 SpriteFrame，绑定前先查询并核对其实际像素宽高、透明边界和旋转/trim 状态是否符合真实尺寸契约。不得用任意缩放、拉伸或修改父节点坐标去掩盖切片尺寸错误；发现不一致时回到切图或生成环节修正。SpriteFrame 绑定可能触发 RAW 尺寸自动写入，绑定后必须再次写回蓝图规定的 UITransform 尺寸并复查锚点、点击热区和覆盖文字。
    - 设置子节点尺寸，再配置父容器 Layout。
    - 最后配置 Widget、项目交互组件、ScrollView 和必要的 EventHandler。
12. 恢复运行时契约：刷新节点收集器，核对按钮路由、项目状态组件默认值、滚动 Content、模板显隐、动画路径、排序边界和业务组件引用。不要批量激活原本用于状态、模板或特效的禁用节点。
13. 从内层到外层调用 `Layout.updateLayout()` 和 `Widget.updateAlignment()`，再重新测量尺寸、边界和点击区域。
14. 按 [验收流程](validate-cocos-content.md) 组合结构、引用、脚本和交互检查。桥接可用时，`validateUI` 能补充基础 UI 约束检查，但不读取效果图或验证视觉位置；其 0 error/0 warning 只能称为“结构校验通过”。独立 Prefab 根不含 Canvas 时按服务 API 使用 `assumeRenderRoot`，场景 Canvas 子树则不启用。修复所有 error；逐条判断 warning，只有与工程约定一致且运行结构完整时才能接受。
15. 保存场景或 Prefab，等待 AssetDB idle，再次检查实际节点树、布局、资源引用、控制器作用域和嵌套 Prefab 状态。

## 视觉验收阶段

16. 有效果图时，通过 MCP 的真实预览截图或服务提供的 Prefab 渲染能力，在工程设计分辨率和相同内容状态下取得真实 PNG，再与按已记录映射生成的设计分辨率参考副本比较，查看叠图和差异图。静态 Prefab 与运行游戏截图的适用边界见 [验收流程](validate-cocos-content.md)。
   - 其他设备尺寸的运行时适配单独检查，沿用工程 fit 设置，不据此改变拼装画布或根节点设计尺寸。
   - 按 [文字验收范围](../references/assemble-cocos-ui/visual-fidelity.md#文字几何与描边) 确定受检节点，在比较整图前逐个核对这些 Label 的实际可见包围框、首字左边界、文本基线、字号、行高、字重和描边；不能只检查 Label 节点中心或 `UITransform` 矩形。
   - 对标题等关键文字记录参考图与真实渲染图的字形 `left/top/right/bottom`；没有这组对照数据时，不能报告文字位置已通过验收。
   - 对“底板 + 文字/图标”复合视觉先对齐底板的位置、尺寸和缩放，再比较覆盖元素相对底板的中心偏移和边距。只比较覆盖元素的画布绝对坐标不能通过验收。
   - 逐项核对切片资源的实际像素宽高与尺寸契约，确认透明留白、trim、九宫格边界和 UITransform 映射没有被导入或自动缩放改变；尺寸不符时视觉验收不通过。
   - 任何文字节点的位置、字号或描边与效果图明显不符时，不得把视觉验收判定为完成。
17. 全部可见元素都有对应美术资源时执行严格比较。非零差异按 [停止条件与交付状态](../references/assemble-cocos-ui/visual-fidelity.md#停止条件与交付状态) 处理，分别报告已通过、未通过和未验证项。
18. 存在缺失美术资源时，精确还原已有资源、文字和几何；只允许缺失资源对应节点保持纯色大致效果。交付时列出这些节点，不能将结果描述为与效果图完全一致。

## 比较与项目派生状态

使用引用收集器或自动绑定组件的工程中，按目标工程约定识别绑定节点。新增、移动或重命名后，通过 MCP 调用工程实际组件的刷新逻辑并检查结果，确认作用域和 key 未发生意外变化；不预设节点前缀、刷新方法或嵌套收集边界。`inspectUILayout`、`inspectComponent` 等桥接辅助方法的参数见服务 [桥接 API](../../cocos-mcp/docs/creator-bridge/api.md)，不在技能中复制调用实现。

精确资源模式下严格比较效果图和真实渲染图。差异图、叠图和报告写入目标工程的 `temp/assemble-cocos-ui/`：

```powershell
python "<技能根目录>/scripts/compare-ui-images.py" --reference "<效果图绝对路径>" --actual "<真实渲染PNG绝对路径>" --diff "<工程目录>/temp/assemble-cocos-ui/diff.png" --overlay "<工程目录>/temp/assemble-cocos-ui/overlay.png" --report "<工程目录>/temp/assemble-cocos-ui/compare.json"
```

退出码为 0 且 `mismatchPixels` 为 0 才表示视觉一致。纯色占位模式可以使用差异图检查几何，但非零差异是预期结果。

## 完成标准

- 规划请求：蓝图包含结构证据、节点来源、控制器作用域、引用、复用、重复内容、状态、布局、适配和可执行拼装顺序，并通过一致性检查。
- 制作请求：实际节点树与蓝图一致；有证据支持的规格修正已记录。
- 业务脚本需要的节点名、组件和引用可解析，收集器作用域内没有重复 key。
- 交互使用工程既有组件和分发方式，点击区域不小于视觉区域，没有重复触发路径。
- Layout、Widget、Mask、ScrollView、项目状态组件、动画、排序边界、嵌套 Prefab 和初始状态经过校验。
- 保存后的 Prefab 能重新打开，结构校验无 error，关键 warning 有明确解释；此结果不代表视觉验收通过。
- “完全一致”的判定统一遵循 [视觉完成门槛](../references/assemble-cocos-ui/visual-fidelity.md#完成门槛)。未达到时按停止条件交付差异证据，不将部分通过描述为制作全部完成。
- 缺少部分或全部美术资源时，只有对应元素使用纯色 Sprite；界面结构、尺寸、位置、文字、交互和已有素材已验收，并列出纯色节点及待替换资源。

## 修改边界

- 在 Prefab 实例上遵守 Creator 层级限制，不删除或移动来自源资源的节点。优先使用属性覆盖和挂载节点；需要改变公共结构时编辑源 Prefab 或明确应用修改。
- 资源操作使用 AssetDB；不要手写 `.meta`、序列化对象 ID、脚本类型 ID 或 Prefab 对象表。
- 不得把整张效果图或大块截图直接作为覆盖 Sprite。可交互、可变化和可复用元素必须保持正确节点、组件和业务结构。
- 大界面按可独立验收的区域分阶段执行。失败时保留 dirty 上下文供撤销，不自动保存未通过校验的结果。
