# 运行时排障与性能分析

适用于 Chrome Web 预览的异常、请求失败、卡顿、CPU 开销与内存保留问题。输入为工程、可复现场景和操作、现象及期望；先确认版本、工程连接及实际预览实例。安装、授权、参数和文件限制统一读取 [MCP DevTools 说明](../../cocos-mcp/docs/DEVTOOLS.md)，不在此维护另一套 API。

## 建立可比较的现场

1. 记录场景、界面、分辨率、操作步骤、资源缓存、是否后台运行及问题条件。
2. 通过 MCP 查询实际业务组件和状态，核对所选预览与工程一致。复用用户的正常预览，保留未保存编辑和游戏进度。
3. 用控制台与网络记录判断异常、资源失败或重复请求，记录实际堆栈、请求 ID 和时间。缺少历史时先连接再复现，不能把没有记录解释为没有问题。

## 按假设采样

- 卡顿/CPU：短时间线覆盖问题操作，找实际主线程长任务、JavaScript 调用和资源处理。空闲与操作场景分开记录，首次加载与稳定运行分开比较。
- 网络/资源：从失败或耗时请求反查真实资源、加载触发点和重复调用，结合工程日志验证，不仅凭文件大小认定瓶颈。
- 内存：用相同进入/退出、创建/销毁流程采集可比较快照，追踪增长对象和保留链。排除正常缓存、异步清理及采样影响后再判断泄漏。
- 渲染/UI：结合真实节点、组件、分辨率和帧时间定位范围。节点数、DOM 加载指标和编辑器计数不等于 Draw Call、GPU 耗时或游戏 FPS。

每次修改对应“现象 → 证据 → 假设 → 最小改动 → 复验”。只要求分析时交付可定位的问题和建议；已授权优化时继续最小修复，不顺带升级引擎、重构业务或替换资源体系。

## 验证与交付

在相同场景、操作、设备/浏览器条件下复验，比较修改前后对应证据，并检查业务交互与视觉。新编译或运行错误先修复再采样。交付实际采样、日志路径和修改对象，区分证据、推断与未验证假设；未实际测量的指标不承诺改善，设备问题仍需设备验收。
