# 效果图一致性与纯色占位验收

输入包含效果图时，本参考是强制流程。目标是在工程设计分辨率和效果图对应的内容状态下还原界面，同时保持界面可交互、可维护并符合工程运行时契约。美术资源是否提供决定视觉元素的验收方式。

## 资源模式判定

对效果图中的每个视觉元素分别判定：

- 用户提供、蓝图明确指定，或工程中已确认唯一对应资源的元素使用精确素材模式。必须绑定该 SpriteFrame、字体或 Prefab，并接受严格像素验收。
- 没有提供对应美术资源，也无法确认唯一工程资源的元素使用纯色占位模式。使用中性纯白 SpriteFrame 配合 `Sprite.color`，按效果图的大致形状、尺寸、位置和层次拼装。
- 同一界面允许两种模式并存。已有资源的元素不能因为其他元素缺资源而降级成纯色或近似素材。

纯色占位只能代表缺失的美术元素。不要使用带 Logo、花纹或图案的默认图，不要寻找风格相近的插画冒充原图，也不要把效果图截图裁块后导入。每个纯色节点都要记录原图区域、占位颜色和待替换资源用途。

## 固定比较基线

保留用户提供的原图，不裁剪、不缩放、不二次压缩。开始拼装前记录：

- 原图像素宽高、方向、色彩模式和透明通道。
- 设计分辨率、适配策略、设备像素比、横竖屏和安全区。
- 当前语言、字体、文案、数值、头像/图标、列表数量与滚动位置。
- 所有状态组的当前分支、节点显隐、按钮状态、进度值和遮罩范围。
- 动画或粒子对应的准确时间点。无法固定帧时，先暂停或把进度设为确定值再截图。

参考图和实测图必须使用同一个基线。尺寸、语言、数据或动画帧不同的两张图不能进入像素比较。

### 直接使用工程设计分辨率

拼装画布直接取工程配置的 `designWidth × designHeight`，全屏 UI 根节点尺寸与其一致。弹窗和可复用控件保留自身尺寸，但位置和尺寸均使用工程设计坐标。工程 fit 设置用于运行时设备适配，不用于按效果图比例扩展拼装画布。

保留原始效果图；尺寸不同时，以宽高比例中的较小值作为统一缩放系数，将整张效果图等比缩放并居中放入设计画布，完整显示所有内容。不得裁切、分别缩放两个轴或为填满画布而放大溢出。记录缩放系数和留白偏移，并生成独立的设计分辨率参考副本用于比较：

```text
scale = min(designWidth / referenceWidth, designHeight / referenceHeight)
offsetX = (designWidth - referenceWidth * scale) / 2
offsetY = (designHeight - referenceHeight * scale) / 2
designLeft = offsetX + referenceLeft * scale
designTop = offsetY + referenceTop * scale
designRegionWidth = referenceWidthOfElement * scale
designRegionHeight = referenceHeightOfElement * scale
```

所有内容的位置、尺寸、间距、字号和行高均使用同一缩放系数，保持原图比例和相对布局。剩余区域保留留白，并记录填充颜色或透明背景；参考副本和实际渲染使用相同填充。不得通过重排、拉伸或裁切原图内容消除留白。

根与节点均为中心锚点时，由设计画布内左上坐标换算全屏根的局部坐标：

```text
x = designLeft + width / 2 - designWidth / 2
y = designHeight / 2 - (designTop + height / 2)
```

其他锚点或嵌套容器按实际父节点尺寸、锚点和位置换算。预览与参考副本均使用工程设计分辨率；其他设备尺寸的运行时适配单独验收，不改变拼装基准。

## 从图像建立可执行规格

按从外到内的顺序测量画布、全屏背景、主面板、功能区域、重复项和叶子视觉。对每个可见元素记录：

- 左、上、宽、高和中心点，以原图左上角为原点。
- 与父容器和相邻元素的水平/垂直间距。
- SpriteFrame、九宫格边界、裁剪方式、混合颜色和透明度。
- 字体资源、字号、行高、字距、对齐、Overflow、描边、阴影和字符串。
- 激活状态、层级顺序以及是否受 Layout、Widget、Mask 或动画控制。

按 [设计分辨率映射](#直接使用工程设计分辨率) 将测量值转换为实际父节点坐标，记录锚点及换算结果，不重复维护另一套坐标公式。

## 素材与文字

- 先从效果图识别素材，再核对用户提供资源、AssetDB、相邻 Prefab、公共 Prefab 和图集。能确认完全对应的资源进入精确素材模式；不能确认时进入纯色占位模式。名称相似但轮廓、留白、九宫格或颜色不同的资源不能替代。
- 复用 SpriteFrame 时保留原始 trim、旋转、九宫格和采样设置。不要用缩放补偿错误留白。
- 人物、图标和复杂纹理保持等比缩放；只有设计为可拉伸区域的底板和条形背景使用 SLICED。
- 字体选择和回退配置遵循 [文字组件规则](ui-rules.md#text-decoration)，记录实际字体及回退节点；不能把回退字体结果称为完全一致。
- 动态文字用固定测试数据复现参考状态。不要把文字烘焙进背景图来通过比较。

### 复合视觉与相对坐标

标题牌文字、按钮文字、图标角标等覆盖元素必须与承载素材一起验收：

- 先在参考图和真实渲染图中分别测量承载素材的 `left/top/width/height`，对齐承载素材后才能调整覆盖元素。
- 同时记录覆盖元素的画布绝对包围框，以及它相对承载素材的中心偏移、四边间距或局部坐标。绝对包围框接近但相对偏移不一致时，仍判定位置错误。
- 会随承载素材移动、缩放或动画的覆盖元素，应放入承载节点子树，或与承载素材共用同一零偏移容器。不得把两者放在互不相关的父节点下分别用世界位置凑齐。
- 比较顺序固定为“承载素材位置与缩放 → 覆盖元素相对位置 → 覆盖元素字形或图标细节”。承载素材尚未对齐时，不得通过移动文字来掩盖底板偏差。

### 文字几何与描边

文字必须按“可见字形”验收，不能用 Label 节点的中心点代替字形位置：

- 从效果图记录每段文字的可见 `left/top/right/bottom`、首字左边界、基线和相邻控件间距；换算到设计分辨率后再确定 Label 的锚点、宽高和坐标。
- 先确定 Label 所属视觉区域和定位语义，再设置 `UITransform.anchorPoint`、Label 水平/垂直对齐与 Overflow，最后换算节点坐标。居中标题应让 Label 节点中心与标题区域中心一致并使用水平/垂直居中；不能保留偏离区域中心的节点，再依赖左对齐或右对齐把字形推到目标位置。
- 按 [文字组件规则](ui-rules.md#text-decoration) 完成配置后，以真实字形包围框核对字号、行高、对齐和字体度量。
- 按参考图测量描边颜色和向外扩张像素，依据 [文字组件规则](ui-rules.md#text-decoration) 配置，并检查描边对可见包围框的影响。
- 按钮文字若有描边或阴影，必须挂在文字节点上并随按钮一起缩放；标题、栏目名、正文和页脚不得机械套用同一字号或字重。
- 字体回退差异列入交付限制；继续校正可测量的字号、基线、字形边界和描边，并说明未通过项。
- 检查范围覆盖界面实际存在的文字类别。新建界面检查全部可见文字；局部修改检查变更节点及受父布局、字体或资源变化影响的区域。标题、正文、按钮等类别按实际存在情况选择，不要求不存在的栏目或页脚。所有受检文字均查看真实渲染，记录范围与未验证项。
- 记录关键文字在参考图与真实渲染图中的字形包围框。仅运行 `validateUI`、仅确认 Label 属性存在，或仅得到 0 个结构错误，都不能作为文字位置正确的证据。

## 真实渲染

静态 Prefab 使用服务的真实内部渲染能力，输出尺寸与所采用的比较参考副本一致。界面依赖业务数据、Widget/项目适配组件、运行时换图、动画或特效时，通过 MCP 获取真实游戏预览画面，并先把运行状态固定到参考图对应状态。工具选择与证据边界见 [任务验收](../../modules/validate-cocos-content.md)。

所有对比产物写入目标工程 `temp/assemble-cocos-ui/`。禁止用编辑器截图、设计工具预览或手工合成图代替 Creator 的真实渲染结果。

## 差异迭代顺序

精确素材模式下，每轮真实渲染后运行 `scripts/compare-ui-images.py`，同时生成差异图、50% 叠图和 JSON 报告。纯色占位模式可用叠图和差异边界校正几何，但不要求占位区域像素相同。按下面顺序修正，避免在父级几何仍错误时微调子节点：

1. 画布尺寸、根节点缩放、适配和整体偏移。
2. 主面板与功能区域的位置、尺寸、锚点和间距。
3. SpriteFrame、SLICED 边界、Mask、裁剪和渲染顺序。
4. 字体、字号、行高、对齐、描边、阴影和字符串。
5. 颜色、透明度、材质、混合模式和抗锯齿来源。
6. 单像素边缘、半像素坐标、细小间距和最终 RGBA 差异。

查看报告中的 `mismatchBounds`、`topMismatchRows` 和 `topMismatchColumns` 定位主要偏差。每次只改有证据指向的属性，重新更新 Layout/Widget、保存、渲染和比较。

## 停止条件与交付状态

差异非零时，先根据证据修正可控的布局、资源和文字配置。只有存在新的可验证原因或修正方案时才继续下一轮；已确认剩余差异依赖缺失资源、无法固定的运行状态或当前不可控制的渲染条件，或同一差异在针对性修正后仍重复出现且没有新证据时，停止盲目迭代。记录参考与实测图、差异报告、已尝试的修正、剩余原因（未查明时明确标记未知）和恢复验证所需条件。

分别报告结构、保存、布局、交互及像素一致性的状态。有实际证据时可报告“布局与交互通过，像素一致性未通过”；没有同状态截图时报告“像素一致性未验证”。这两种状态均不代表完全一致；用户要求精确还原时，该要求仍为未完成。不得降低阈值、修改参考图内容或隐藏差异来宣布通过。

## 完成门槛

全部视觉元素都有对应资源时，同时满足以下条件才能报告完全一致：

- 参考图与真实渲染图像素宽高完全相同。
- 比较报告 `mismatchPixels` 为 0，`maxChannelDifference` 为 0。
- 没有占位素材、临时文字、缺失字体或未固定的动态内容。
- 可交互元素仍是独立节点，并保留项目按钮、引用绑定、状态组件和 ScrollView 等工程契约。
- 未把整张效果图或局部大截图作为覆盖层隐藏真实 UI。

存在未提供的美术或字体资源时，可以报告“大致效果拼装完成”，但必须同时满足：

- 只有缺失资源对应的元素使用纯色 Sprite；字体回退符合 [文字组件规则](ui-rules.md#text-decoration)。
- 已有资源、界面结构、节点尺寸、位置、间距、层级、文字内容和交互均已验收。
- 交付清单列出每个纯色节点、默认字体节点和所需的最终资源。
- 没有把近似结果描述为完全一致，也没有为通过像素检查而降低阈值。
